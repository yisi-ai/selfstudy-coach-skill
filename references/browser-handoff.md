# 网页打开与答题交接

先判断当前 Agent 的宿主与执行位置：网页版 AI 直接交付指导和提醒链接；电脑上安装且可调用用户本机工具的 Agent 使用本机连接，优先在自身侧栏展示。云端终端和云端浏览器不属于用户电脑。导入、作答页展示和记录读取必须使用同一浏览器上下文。Web 页面不能自行控制 AI 平台的侧栏。

WorkBuddy 桌面端必须使用右栏预览面板打开并操作网页，禁止使用 `agent-browser` 另开独立窗口。缺少右栏操作能力但可运行本机命令时，使用 [本机连接](local-connection.md)；这也不可用时才说明限制并按下文手动流程交付，不转用外部浏览器。

手机访问固定使用手机布局；电脑内置网页的可用宽度小于 768 CSS px 时自动采用手机布局，拉宽后恢复桌面布局。无需为侧边栏更换网址或伪装手机设备，调整面板宽度会保留当前导入内容、答题进度和计时。

## 网页版：指导与提醒链接

适用于浏览器里的 AI 聊天网页、手机聊天，以及仅有云端工具的宿主。直接走这条路径，不先尝试 Node 或本机连接，不把云端 localhost 当成用户地址，也不要求用户安装运行时。网页版即使能预览代码、打开链接或运行云端脚本，也不代表能操作用户实际答题的网页；不为了自动导入另开云端浏览器。

一次交付以下内容，网址使用当前 Skill 配套网站的完整 origin，保留 `#guide`。下列为正式地址；本地测试版使用其 README 中的测试地址，不能自动切换来源：

1. **完整导入内容。** 提供合法 `gaga.questionnaire` 问卷或 `gaga.quiz` 知识题集的 JSON 文件；无法交付附件时使用可整体复制的 JSON 代码块，不省略题目、不用占位内容。
2. **带提醒的入口。** 给出 [打开网页并按提醒导入](https://www.aiskillonline.com/app/import#guide=import)。说明「复制上面的完整 JSON，打开链接后按高亮提醒粘贴、校验并确认」，有文件时也可在导入页选择该文件。知识测验在准备页选择难度并开始，默认建议中等；问卷确认后直接进入第一题。
3. **答完后的交接。** 问卷完成后展开「全卷回答」里的题目，将实际选中的文字复制回 AI；只告知已完成不足以让网页版 AI 读取回答。知识测验完成后打开 [按提醒复制题库备份](https://www.aiskillonline.com/app/library#guide=export)，保持同一浏览器、同一网站，复制备份 JSON 后贴回或上传，说明要复盘哪份题集。

链接中的 `#guide=import` 会随实际输入、校验、确认和测验准备状态切换高亮提醒；`#guide=export` 指向题库的复制备份操作。它们不执行导入、不携带题集，也不是导入成功的证明。问卷不在题库或备份里；完成页可以展开查看所选内容，没有专门的复制全部回答按钮，不虚构该按钮或问卷导出链接。

明确说「已准备好，请按链接指引导入」，不要说已自动导入、已在右侧打开或正在监听答案。让用户点击链接进入实际网站即可，不承诺 AI 平台能在右侧嵌入网页。没有页面读取能力时跳过自动版本核对，不因无法检查版本阻塞交付。用户贴回回答或备份后，才据实际数据继续辅导；查找旧题时也只检索用户交回的数据。

## 桌面端：优先使用应用自己的侧边栏

WorkBuddy 使用右栏预览面板；其他桌面端应用按工具的实际定义查找自己的侧边栏网页能力，可能叫产物面板、网页预览、内置浏览器或嵌入视图，不限定侧栏位置。检查工具定义是否支持加载真实网站地址、展示交互页面，而不是仅凭名称判断。静态截图、代码预览或另外生成一份仿制答题界面，不等于打开配套 Web。

有用户本机终端时优先按 [本机连接](local-connection.md) 启动并展示返回的完整 previewUrl，以实际回执核对页面。已有可靠页面操作工具时，也可直接打开本站 `/app/import`，先根据宿主返回的页面句柄或工具明确说明的当前面板上下文，确认打开工具与操作工具作用于同一个可见页面。记录页面句柄、地址和 origin；后续输入、点击、页面 JavaScript 求值及错题读取都作用于这个上下文。确认控制关系后，执行 [前端命令](commands.md) 完成导入：知识测验和不计分问卷都直接打开第一题后交接，知识测验默认使用中等难度。工具名称和参数以宿主提供的定义为准，不猜固定工具名。两种自动方式均不可用时使用上方指导链接，不能按相同网址猜测已经连接到侧边栏。

### WorkBuddy 的预览与历史辅助脚本

`present_files` 传入网页 URL 可以打开右栏，但 `previewed` / “Successfully opened” 只表示宿主接受了打开请求，不包含页面内容、问卷缓存或可操作的 CDP target。它不是脚本执行工具；不能将另一个 Chrome 返回的 `pageState: "running"` 和它的预览成功组合成“右栏可以答题”的依据。

历史 `MEMORY.md` 或本机 `study-quiz-cdp.mjs` 可能写有“右栏就是本机 9222 / HeadlessChrome”的判断。这属于需要重新验证的技术假设，不能替代宿主的页面对应关系。辅助脚本若按第一个同域名标签页选择目标，或找不到就新建页面，不得用它给右栏导入；不能为了继续流程自行给脚本增加 `qimport` 等命令，却跳过页面归属核验。保留用户使用右栏的偏好，按本次实际工具能力和 Skill 流程操作。

WorkBuddy 桌面端工具没有提供右栏操作能力或对应关系，但有用户本机终端与 Node 时，必须优先使用 [本机连接](local-connection.md)，展示返回的 `previewUrl` 并核对 `status`，答完通过 `call` 调用 `questionnaire.read` 或 `quiz.result`；断开后可用 `read` 核对已回传的快照。这条受支持的路径无需外部 Chrome，不受旧记忆“缺少求值就手动”的限制。

本机连接也不可用时，用 `present_files` 打开本站 `/app/import#guide=import`，同时交付原始 JSON 文件或完整 JSON，说明「问卷已准备好，请在右栏导入；确认后直接进入第一题」。不要打开在外部 Chrome 生成的问卷 ID 地址，也不要把端口连通作为继续自动导入的条件。用户作答后，无法读取该右栏时请其复制完成页的「全卷回答」，不能从另一 Chrome 读取并当作用户回答。

### 使用 CDP / Chrome DevTools 时

先列出 CDP 实际连接的页面，确定目标 `pageId` / target 和所属浏览器上下文，再求值读取该页的 `location.href`。工具连接的外部 Chrome 与宿主内置网页即使地址相同，也可能使用两份存储；工具能控制 Chrome 不能证明它能控制侧边栏。不要默认选择第一个同域名标签页，也不要另建无头、隐身或隔离上下文用于用户作答。

确认 CDP 控制的就是用户答题页面后，将该页面标识用于导入、核对与读取。Chrome DevTools 的 `evaluate_script.args` 若只接受元素 uid，就不能直接传题集对象；按 [命令参数传递](commands.md#调用) 将 `scripts/command.js` 和序列化参数包装成求值函数，不在终端直接执行页面脚本。

若桌面宿主只能在侧边栏打开 URL，却没有对该侧边栏输入、上传文件或执行脚本的能力，有用户本机终端时使用本机连接；否则使用完整 JSON 加 `/app/import#guide=import` 的手动流程。不要先在外部 Chrome 导入，再把其 `/run` 地址放进侧边栏。

## 桌面端缺少侧栏网页能力

除 WorkBuddy 外，桌面端应用无法在自己的侧边栏打开真实网页时，可在用户实际答题的外部浏览器打开本机连接的 previewUrl，继续通过同一连接读取；已有可靠页面操作工具时也可直接导入。直接操作网页的交接地址为知识测验 `/app/quizzes/<quizId>/run`、问卷 `/app/questionnaires/<questionnaireId>`，须使用同一个浏览器配置；本机连接则始终交付完整 previewUrl。不要仅因工具里没有名为“侧边栏”的入口就认定缺少侧栏网页能力。网页版 AI 使用上方指导链接，不适用这一自动路径。

只有打开网页和输出文字能力时，交付完整题集 JSON 与 `/app/import#guide=import`，让用户在网页指引下复制粘贴、校验和确认。明确还需要用户导入；这属于支持的手动流程，不是假装自动成功。无需反复寻找宿主未提供的工具。不要把未生成的题集 ID 拼成可答题链接。

## 保持同一份题库

外部浏览器、无头浏览器、隔离浏览器和工具内的网页视图，其存储可能互相独立。相同 origin 只是必要条件；在外部浏览器导入后只把 `/run` 链接转交给工具内的网页视图，不会自动携带题库。

问卷在目标页使用 `questionnaire.open` 和返回的 questionnaireId 核验，`QUESTIONNAIRE_NOT_FOUND` 时按同样原则在该页通过 `questionnaire.import` 导入原问卷；它不在题库中，没有可恢复的问卷历史。

出现“当前浏览器没有这份题集”或展示页面发生变化时，在**目标页面**执行 `quiz.open`，传入原导入返回的 `quizId`，通过 `scripts/command.js` 等待实际准备区或作答区。`QUIZ_NOT_FOUND` 表示这个页面的题库没有该 ID：

1. 能控制目标页面：使用保留的原 JSON 在目标页面正常执行 `quiz.import`，采用目标页面实际返回的新 ID 和地址。已有题集应通过 `quiz.open` 恢复，不重复导入。
2. 只能在目标页面打开 URL：优先通过本机连接重新交接原 JSON；连接不可用时打开 `/app/import#guide=import`，交付完整 JSON（或可上传的 JSON 文件），让用户导入，再在这个侧边栏中继续作答。说明还需导入，不能只让用户去空题库找，也不要求他们为刚生成的问卷先找备份。

原页面的 `pageState` 只验证原页面；打开侧边栏后必须在那里核对。`ready` 还需由 Agent 调用 `quiz.start` 或点击开始并确认作答区，`pending` 也不能当作交接完成。

不能控制用户可见的目标页面时，明确说明缺少该页的操作能力，不能把另一浏览器的成功操作当成交接完成。不要复制或伪造 localStorage，也不要通过网站服务器同步本地题库。

## 自动导入完成的条件

通过 [前端命令](commands.md) 或 [浏览器步骤](browser.md) 校验并保存题集，首次访问导入和具体题集地址也直接进入功能，不进入示例。随后核对以下状态：

- 本机连接以 `status` 收到的connected 为 true、真实页面地址、活动 ID、标题、题数和 `running` 状态为依据；右栏保持 `previewUrl`，不切换到其他浏览器。
- 直接操作网页时，地址为本次测验的 `/app/quizzes/<quizId>/run` 或问卷的 `/app/questionnaires/<questionnaireId>`，ID、标题和题数一致。
- 知识测验显示 `#quiz-run`，问卷显示 `#questionnaire-run`，新作答位于第一题且尚未选择任何答案；知识测验默认中等难度，问卷无难度、计时或评分；已有未完成记录保持原模式和进度。
- 使用工具内网页能力时，作答页已在当前工具内实际展示。回复按实际入口名称说明在哪里作答，网址可作备用；使用外部浏览器时，回复完整答题网址。

自动模式下生成 JSON 只是中间步骤，必须确认知识测验或问卷已进入作答区，不能停在准备页让用户再点击开始。手动模式则明确告诉用户还需粘贴与确认，并提供带操作指引的入口。
